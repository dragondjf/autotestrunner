## 1. 项目概述

### 1.1 项目背景

为测试团队提供一个轻量级的 Web-UI 自动化测试管理平台，核心链路为：**录制生成脚本 → 任务化执行 → 报告产出**。录制是整条链路的入口，直接决定脚本质量与用户上手成本。

系统提供两种互补的录制模式：**浏览器录制**（用户在真实浏览器中手动操作，系统被动捕获）与 **AI 录制**（用户输入自然语言任务描述，AI Agent 自主探索执行）。

### 1.2 项目目标

| 目标 | 说明 |
|------|------|
| 录制管理 | 支持 AI 录制、浏览器录制两种模式的项目增删改查，统一管理 |
| 测试任务 | 支持任务的创建、参数化、执行和自动重试 |
| 测试计划 | 支持测试计划的串行编排与执行 |
| 测试报告 | 生成包含截图和视频的完整测试报告，支持 HTML/PDF 导出 |

### 1.3 用户角色

| 角色 | 描述 |
|------|------|
| 测试工程师 | 核心用户，创建录制项目、执行测试任务、查看报告 |
| 开发 / 产品 | 通过 AI 录制以低门槛参与（自然语言描述任务） |

### 1.4 术语表

| 术语 | 定义 |
|------|------|
| 录制项目（Project） | 录制产物载体，`type: 'ai' \| 'browser'`，含脚本内容与参数 Schema |
| 录制会话（Record Session） | 一次浏览器录制过程，由 Runner 侧 `RecordingSession` 封装 |
| Agent 会话（Agent Session） | 一次 AI 录制过程，由 Backend 侧 `AgentSession` 封装，可跨请求复用 |
| 调试会话（Debug Session） | 交互式调试过程，支持高亮/拾取/单步执行 |
| 定位策略（Locator Strategy） | 生成元素候选定位器的策略：`default` / `tolerant` / `robust` / `semantic_first` / `semantic` |
| 步骤（Step） | 标准化操作单元：`{ method, params, locator }` |
| 快照（Snapshot） | 任务创建时复制的项目脚本，编辑项目不影响已创建任务 |
| SSE | Server-Sent Events，AI 录制实时事件流的传输方式 |

## 2. 整体架构与核心链路

### 2.1 系统架构

```
+-------------------+      HTTP + 回调(X-Internal-Token)  +-------------------+
| web-ui (Backend)  | <---------------------------------> |  runner (Runner)  |
| :3000             |   POST /record/start 等             |  :9377            |
|                   |                                     |                   |
| agent.routes.ts   |   POST /api/agent/run (SSE)         |  recording.ts     |
| agent-runner.ts   |   —— 仅 Backend 内部 ——>            |  recorder-script  |
| page/exec routes  |                                     |  debug-session.ts |
+-------------------+                                     +-------------------+
        |                                                          |
        v                                                          v
+-------------------+                                     +-------------------+
| smartbrowser 包    |                                     |  Playwright       |
| AgentExplorer     |                                     |  Chromium/Firefox |
| Planner/Locator   |                                     |  WebKit           |
+-------------------+                                     +-------------------+
```

- **web-ui（Backend，:3000）**：面向前端的 HTTP/SSE API，承载 AI 录制全流程与录制项目管理。
- **runner（Runner，:9377）**：独立进程，持有 Playwright 浏览器实例，承载浏览器录制与交互调试。
- **smartbrowser**：AI 探索引擎（`UiMcpAgentExplorer`），被 Backend 的 `agent-runner.ts` 调用。
- **shared**：跨进程契约类型（`RecordStartPayload`、`RecordedAction`、`DebugSessionPayload`、`DEBUG_EVENTS` 等）与环境配置。
- **数据库**：SQLite 本地存储，所有数据保存在服务本地。

### 2.2 核心链路

```
录制生成脚本（浏览器录制 / AI 录制） → 步骤转脚本落库 → 任务化执行（串行队列） → 报告产出（截图/视频/导出）
```

### 2.3 两种录制模式对比

| 维度 | 浏览器录制（Browser Recording） | AI 录制（AI Recording） |
|------|------|------|
| 交互方式 | 用户在真实浏览器中手动操作，系统被动捕获 | 用户输入自然语言任务描述，AI Agent 自主探索执行 |
| 适用人群 | 熟悉业务流程的测试人员 | 任何角色（含开发、产品） |
| 产物 | 原始操作事件流 → 标准步骤 | AI 执行轨迹（含截图/推理）→ 标准步骤 |
| 脚本质量 | 依赖用户操作规范性 | 依赖 LLM 规划质量，自动生成语义化定位 |
| 成本 | 无 LLM 成本，确定性高 | 有 LLM 成本，效率高 |
| 典型场景 | 精确回放复杂交互（拖拽、悬停、键盘组合） | 快速冒烟、探索性测试、流程发现 |

## 3. 功能需求

> 优先级定义：P0 = Must（首版必须），P1 = Should（一期内），P2 = Could（二期）。

### 3.1 录制管理（含 AI 录制与浏览器录制）

> **界面实现基准**：AI 录制界面以 `packages/web-ui/frontend/index.html`（SmartBrowser Agent 观测台）、浏览器录制界面以 `packages/web-ui/frontend/inspect.html`（Playwright 渐进式调试器）为准；第 4 章对应页面交互描述均以这两个真实实现为基准。

录制管理是平台入口，统一承载 AI 录制与浏览器录制两种模式的项目管理、会话管理与产物落库。两种录制产物统一落入项目模型（`name / type / scriptContent / paramsSchema`），后续任务、计划、报告链路无差别消费。

#### 3.1.1 录制项目管理（REC-P）

| 编号 | 功能 | 优先级 | MoSCoW | 描述 |
|------|------|--------|--------|------|
| REC-P01 | 项目列表 | P0 | Must | 展示所有录制项目，支持分页、搜索、类型筛选、状态筛选 |
| REC-P02 | 创建项目 | P0 | Must | 输入名称、类型（ai / browser）、描述、脚本内容、参数 Schema；默认状态 `draft` |
| REC-P03 | 编辑项目 | P0 | Must | 修改项目所有字段（名称、描述、类型、脚本、参数 Schema、状态） |
| REC-P04 | 删除项目 | P0 | Must | 物理删除，关联任务同时删除 |
| REC-P05 | 查看项目 | P1 | Should | 展示项目详细信息 |
| REC-P06 | 项目状态管理 | P2 | Could | `draft` / `ready` / `archived` 三种状态 |

**用户故事与验收标准**

**REC-P01 项目列表**（Must）
- 用户故事：作为测试工程师，我希望在列表页查看所有录制项目并支持搜索、筛选、分页，以便快速定位目标项目。
- 验收标准：
  - AC-P01-1：列表按创建时间倒序分页展示，默认每页 10 条，支持分页切换。
  - AC-P01-2：支持按名称关键词搜索；支持按录制类型（ai/browser）与状态（draft/ready/archived）组合筛选。
  - AC-P01-3：列表项展示项目名称、录制类型、状态、创建时间、最近执行状态、操作按钮（查看/编辑/删除）。
  - AC-P01-4：加载中展示骨架屏，操作成功后以 Message 提示并刷新列表。
- 边界与异常：无数据时显示空态引导与「创建第一个录制项目」双入口（AI 录制 / 浏览器录制）；搜索无结果时提示「未找到匹配项目」。

**REC-P02 创建项目**（Must）
- 用户故事：作为测试工程师，我希望创建项目时选择录制类型并填写必要信息，以便开始录制。
- 验收标准：
  - AC-P02-1：项目名称必填且不可与已有项目重名；录制类型必选（AI 录制 / 浏览器录制）。
  - AC-P02-2：类型切换时表单区联动切换，已填写的公共字段（名称/URL/描述）保留。
  - AC-P02-3：AI 录制需填写自然语言任务描述（提供示例占位符），点击「生成脚本」进入执行界面。
  - AC-P02-4：浏览器录制需配置定位策略与最大时长，点击「启动录制」打开浏览器。
  - AC-P02-5：保存成功后生成 `draft` 状态项目并进入对应录制流程。
- 边界与异常：名称为空/重名时表单校验拦截并提示；目标 URL 必填且校验 URL 格式；描述可选。

**REC-P03 编辑项目**（Must）
- 用户故事：作为测试工程师，我希望修改项目信息与脚本，以便迭代测试内容。
- 验收标准：
  - AC-P03-1：可修改名称、描述、类型、脚本内容、参数 Schema、状态，保存后更新时间戳。
  - AC-P03-2：已创建任务的脚本快照不受项目编辑影响。
- 边界与异常：修改脚本前若已存在关联任务，提示「仅影响后续新任务」。

**REC-P04 删除项目**（Must）
- 用户故事：作为测试工程师，我希望删除不再使用的项目，以便保持列表整洁。
- 验收标准：
  - AC-P04-1：点击删除弹出二次确认对话框（提示影响范围），确认后物理删除。
  - AC-P04-2：删除项目时其关联任务一并删除。
- 边界与异常：若项目存在运行中任务，拦截删除并提示「任务执行中，无法删除」。

**REC-P05 查看项目**（Should）
- 验收标准：
  - AC-P05-1：展示项目全部字段，含脚本内容、参数 Schema、关联任务列表。
  - AC-P05-2：提供「创建任务」「重新录制」「编辑」快捷入口。
- 边界与异常：`archived` 项目的「创建任务」入口置灰并提示原因。

**REC-P06 项目状态管理**（Could）
- 验收标准：
  - AC-P06-1：支持 `draft → ready → archived` 状态流转，仅 `ready` 状态可创建任务。
  - AC-P06-2：`archived` 项目可恢复为 `ready`。
- 边界与异常：非 `ready` 项目创建任务被拦截并提示状态原因。

#### 3.1.2 浏览器录制（REC-B）

| 编号 | 功能 | 优先级 | MoSCoW | 描述 |
|------|------|--------|--------|------|
| REC-B01 | 会话生命周期管理 | P0 | Must | 启动/停止/暂停/恢复/清空/超时保护/异常兜底 |
| REC-B02 | 用户操作捕获 | P0 | Must | 监听捕获 click/input/select/keydown/scroll/navigation/popup/hover 等操作 |
| REC-B03 | 多级定位策略 | P0 | Must | 五种定位策略 + 候选定位器 + 元素元信息 |
| REC-B04 | 实时心跳与状态回传 | P0 | Must | 1s 心跳、iframe 监听状态、失联判定 |
| REC-B05 | 录制数据结构化 | P0 | Must | `RecordedAction` 统一字段契约 |
| REC-B06 | 视频录制 | P1 | Should | Playwright `recordVideo`，MP4 入库关联报告 |
| REC-B07 | 交互式调试 | P1 | Should | 高亮/拾取/单步执行/热键/事件回调 |

**用户故事与验收标准**

**REC-B01 录制会话生命周期管理**（Must）
- 用户故事：作为测试工程师，我希望能够启动、暂停、恢复、清空、停止浏览器录制会话，以便精确控制录制过程。
- 验收标准：
  - AC-B01-1：启动录制需提供目标 URL；启动成功返回会话 ID 并打开浏览器窗口。
  - AC-B01-2：停止录制保存全部已捕获动作并清理浏览器；`max_record_time`（默认 600s）到期自动停止。
  - AC-B01-3：暂停期间捕获动作丢弃；恢复继续捕获；「清空」需二次确认并重置动作列表。
  - AC-B01-4：浏览器启动失败/页面崩溃时，回调 `status: failed` 并携带错误信息。
  - AC-B01-5：停止操作为幂等，重复停止不产生副作用。
- 边界与异常：剩余 60s 时计时器以警告色提示；心跳超时判定会话失联，提供「强制结束」入口，已收到的动作仍可保存。

**REC-B02 用户操作捕获**（Must）
- 用户故事：作为测试工程师，我希望浏览器录制能准确捕获我的操作并转为标准步骤，以便生成可回放的脚本。
- 验收标准：
  - AC-B02-1：按捕获时机规则监听 click/dblclick、input、select、keydown、scroll、navigation、popup/dialog、hover 各类操作。
  - AC-B02-2：同一输入框连续键入合并为一条 input；仅捕获 Enter/Tab/Escape 关键键。
  - AC-B02-3：scroll 防抖 500ms；hover 目标在 `hover_delay_ms`（默认 1000ms）后记录。
- 边界与异常：非关键键不产生噪音动作；跨 iframe 操作记录 `frame` 标识；未监听 iframe 以警告色提示（可能漏录）。

**REC-B03 多级定位策略与候选定位器**（Must）
- 验收标准：
  - AC-B03-1：每条动作按所选策略生成有序候选定位器数组 `candidates`，回放时依次降级尝试。
  - AC-B03-2：携带完整 `meta`（tag/text/role/ariaLabel/placeholder/id/name/type/classes/cssPath/xpath/attributes）。
  - AC-B03-3：五种策略按规则生成候选（default/tolerant/robust/semantic_first/semantic）。
- 边界与异常：元素无 id/无文本时，策略自动降级到 css/xpath 组合定位。

**REC-B04 实时心跳与状态回传**（Must）
- 验收标准：
  - AC-B04-1：Runner 按 `RECORD_HEARTBEAT_INTERVAL`（默认 1s）上报心跳，含会话状态、`raw_actions`、`frames` 信息。
  - AC-B04-2：心跳与结果回调携带 `X-Internal-Token`，未携带或无效返回 401。
  - AC-B04-3：Backend 依据心跳刷新「录制中」状态；心跳连续超时判定会话失联。
- 边界与异常：单次心跳丢失不应立即判定失联，需连续超时才转「失联」态。

**REC-B05 录制数据结构化**（Must）
- 验收标准：
  - AC-B05-1：`RecordedAction` 包含 action/selector/candidates/meta/ts 必填字段，value/frame/url/extra 可选。
  - AC-B05-2：所有动作带时间戳，回放可严格还原操作顺序。
- 边界与异常：未知操作类型记录到 `extra` 且不中断录制。

**REC-B06 视频录制**（Should）
- 验收标准：
  - AC-B06-1：录制会话开启 `recordVideo`，产物为 MP4，路径写入报告目录。
  - AC-B06-2：报告详情中可播放视频，并与步骤日志关联展示。
- 边界与异常：无头环境缺依赖导致录屏失败时，给出具体原因提示且不影响动作数据。

**REC-B07 交互式调试**（Should）
- 用户故事：作为测试工程师，我希望在录制/编辑过程中与页面实时交互，以便校准定位与验证步骤。
- 验收标准：
  - AC-B07-1：支持 highlight、pick_mode 及 step_click/input/select/scroll/navigate/wait/assert/extract/screenshot/script 单步命令。
  - AC-B07-2：页面内热键 Ctrl+Shift+U（拾取）/H（高亮）/I（检查）/D（调试）可用。
  - AC-B07-3：命令结果通过事件回调（started/page_ready/command_result/step_started/step_finished/step_failed/log/error/stopped）回传。
- 边界与异常：单步命令执行超时返回 `step_failed` 并附错误原因。

#### 3.1.3 AI 录制（REC-A）

| 编号 | 功能 | 优先级 | MoSCoW | 描述 |
|------|------|--------|--------|------|
| REC-A01 | 自然语言任务发起 | P0 | Must | 提交 instruction + url，SSE 流式返回 |
| REC-A02 | Agent 探索循环 | P0 | Must | 快照→规划→执行→观察循环，max_steps 默认 25 |
| REC-A03 | 实时步骤事件流 | P0 | Must | 11 类 SSE 事件契约 |
| REC-A04 | 会话复用与多轮任务 | P0 | Must | resume/keep_alive/GC 回收 |
| REC-A05 | QA 问答模式 | P1 | Should | 只观察不操作，回答页面问题 |
| REC-A06 | 卡死检测与自动重规划 | P0 | Must | 重复动作/无进展触发重规划，上限 3 次 |
| REC-A07 | 定位自愈 | P1 | Should | 定位失败交 LLM 修复重试 |
| REC-A08 | 步骤转脚本 | P0 | Must | 一键转为标准步骤流，落入 scriptContent |
| REC-A09 | LLM 配置管理 | P0 | Must | 供应商/模型/Key/温度读写，请求级覆盖 |
| REC-A10 | 会话观测 | P1 | Should | 会话列表/事件回放/实时截图 |

**用户故事与验收标准**

**REC-A01 自然语言任务发起**（Must）
- 用户故事：作为任意角色（含开发、产品），我希望用自然语言描述测试任务即可发起 AI 录制，以便无需掌握脚本语法即可生成自动化脚本。
- 验收标准：
  - AC-A01-1：提交 instruction + url 后启动 Agent，SSE 流式返回事件。
  - AC-A01-2：LLM 未配置时，AI 录制入口置灰并引导配置弹窗（跳转 LLM 配置页）。
  - AC-A01-3：URL 格式非法时校验拦截并提示。
- 边界与异常：SSE 断连后自动重连（指数退避），重连后通过 `/events` 回放补齐缺失事件。

**REC-A02 Agent 探索循环**（Must）
- 验收标准：
  - AC-A02-1：按 snapshot → LLM 规划 → 执行动作 → 观察结果 循环推进，直到完成或达到 max_steps。
  - AC-A02-2：达到 max_steps 未完成时返回 `task_failed`（含已完成步数）。
- 边界与异常：LLM 返回非法动作 JSON 时记录 `llm_error` 并触发重规划，不中断会话。

**REC-A03 实时步骤事件流**（Must）
- 验收标准：
  - AC-A03-1：按契约推送 11 类事件（session_started/step_started/step_finished/step_failed/llm_request/llm_response/llm_error/task_complete/task_failed/session_closed/error），data 内含 session_id。
  - AC-A03-2：`step_failed` 携带错误信息与截图，前端可展开失败详情。
- 边界与异常：事件环形缓冲保留最近 1000 条，供断线重连回放。

**REC-A04 会话复用与多轮任务**（Must）
- 验收标准：
  - AC-A04-1：`resume: true` 在既有浏览器上下文上继续新任务，保留登录态。
  - AC-A04-2：`keep_alive: true` 在 SSE 结束后保留浏览器供后续复用。
  - AC-A04-3：空闲会话 30 分钟由 GC 自动回收。
- 边界与异常：会话已过期后 resume 返回明确错误并提示新建会话。

**REC-A05 QA 问答模式**（Should）
- 验收标准：
  - AC-A05-1：`mode: 'qa'` 时 Agent 只观察不操作，针对页面内容回答问题。
- 边界与异常：QA 模式禁止执行破坏性动作（点击提交、表单填写等）。

**REC-A06 卡死检测与自动重规划**（Must）
- 验收标准：
  - AC-A06-1：连续 3 次相同动作或连续 5 次无新 URL/新元素时触发重规划。
  - AC-A06-2：重规划最多 3 次，超过则判定 `task_failed`。
- 边界与异常：触发重规划时时间线插入警告条「检测到重复操作，已重新规划」，等待可感知。

**REC-A07 定位自愈（Locator Heal）**（Should）
- 验收标准：
  - AC-A07-1：步骤定位失败时，将候选定位器与页面快照交 LLM 修复并重试；仍失败上报 `step_failed`。
- 边界与异常：自愈重试设置上限，避免无限循环消耗。

**REC-A08 步骤转脚本**（Must）
- 用户故事：作为测试工程师，我希望将 AI 执行轨迹一键转为标准测试脚本，以便保存为可复用的录制项目。
- 验收标准：
  - AC-A08-1：一键将 AI 执行轨迹转换为 `{ method, params, locator }` 标准步骤流，落入 `scriptContent`。
  - AC-A08-2：转换产物与浏览器录制产物同构，可被任务/计划/报告链路无差别消费。
- 边界与异常：转换前提供预览，转换后可按 REC-C01 人工编辑。

**REC-A09 LLM 配置管理**（Must）
- 验收标准：
  - AC-A09-1：支持读写 LLM 供应商、模型、API Key、温度等配置。
  - AC-A09-2：支持请求级 `llm_config` 覆盖，便于多模型对比。
- 边界与异常：API Key 服务端存储，不下发前端明文。

**REC-A10 会话观测**（Should）
- 验收标准：
  - AC-A10-1：会话列表展示 status、steps_completed/failed、last_active、screenshot_available。
  - AC-A10-2：事件回放（SSE，环形缓冲 1000 条）；实时截图（LRU 缓存上限 10MB）。
- 边界与异常：截图缓存淘汰后返回 404 并提示重新获取。

### 3.2 测试任务管理（TSK）

> 任务 = 脚本/资源 + 调度方式 + 执行历史。创建方式升级为 **3 步分步表单**，支持上传脚本与批量资源文件，支持按时间 / 按次数循环执行，每次迭代独立沉淀历史并可回放。

| 编号 | 功能 | 优先级 | MoSCoW | 描述 |
|------|------|--------|--------|------|
| TSK-01 | 任务列表 | P0 | Must | 展示所有测试任务，支持按项目、状态、浏览器类型过滤 |
| TSK-02 | 创建任务（分步表单） | P0 | Must | 4 步向导：①基本信息 → ②脚本与资源 → ③执行调度 → ④确认创建 |
| TSK-03 | 脚本与资源上传 | P0 | Must | 上传脚本（Playwright JS/PY）；批量上传测试资源文件（所有类型、多个） |
| TSK-04 | 编辑任务 | P0 | Must | 修改浏览器类型/路径、重试次数、参数；脚本快照不可更新 |
| TSK-05 | 删除任务 | P0 | Must | 物理删除（含脚本/资源/历史） |
| TSK-06 | 执行任务 | P0 | Must | 手动触发，加入全局串行队列；点击「执行」跳转执行监控页 |
| TSK-07 | 任务重试 | P0 | Must | 失败自动重试（次数可配），完全重新执行，指数退避 |
| TSK-08 | 执行调度 | P0 | Must | 手动 / 按时间循环（天·时·分·秒）/ 按次数循环（迭代 N 次） |
| TSK-09 | 执行监控 | P1 | Should | 实时日志、进度、截图、当前迭代 x/N，可停止执行 |
| TSK-10 | 执行历史与回放 | P1 | Should | 每次迭代独立历史记录；回放视图与执行监控页一致 |

**用户故事与验收标准**

**TSK-01 任务列表**（Must）
- 用户故事：作为测试工程师，我希望按项目/状态/浏览器筛选任务，以便掌握任务全貌。
- 验收标准：
  - AC-TSK-01-1：支持按 projectId、status、browserType 过滤与分页。
  - AC-TSK-01-2：列表展示任务名、所属项目、状态、浏览器、调度方式、最近执行时间。
  - AC-TSK-01-3：运行中/重试中任务状态自动刷新（轮询）。
- 边界与异常：运行中任务不可删除/编辑（拦截提示）。

**TSK-02 创建任务（分步表单）**（Must）
- 用户故事：作为测试工程师，我希望通过分步向导创建测试任务（脚本 → 调度 → 确认），以便快速配置一次测试。
- 验收标准：
  - AC-TSK-02-1：向导共 4 步，可前进/后退，上一步校验未通过不可进入下一步。
  - AC-TSK-02-2：第 1 步填写任务名称（必填）与任务描述（选填）。
  - AC-TSK-02-3：第 2 步脚本来源二选一：上传脚本文件（JS/PY）或从录制项目选择；可批量上传资源文件。
  - AC-TSK-02-4：第 3 步执行调度三选一：手动 / 按时间循环 / 按次数循环。
  - AC-TSK-02-5：第 4 步展示任务摘要（名称/描述/脚本/资源/调度）与脚本预览，可「保存」或「保存并立即执行」。
- 边界与异常：非法格式/超限文件给出具体错误并定位到对应文件。

**TSK-03 脚本与资源上传**（Must）
- 验收标准：
  - AC-TSK-03-1：脚本支持 Playwright JavaScript / Python，上传后解析与语法校验。
  - AC-TSK-03-2：测试资源文件支持**所有类型、多个文件、批量上传**；脚本运行时可按路径引用。
  - AC-TSK-03-3：上传文件带大小/数量校验，超限给出提示。
- 边界与异常：资源文件与脚本随任务存储，任务删除时一并清理。

**TSK-04 编辑任务**（Must）
- 验收标准：
  - AC-TSK-04-1：可修改名称、浏览器类型/路径、参数、maxRetries、调度配置。
  - AC-TSK-04-2：`scriptSnapshot` 不可更新，保持创建时快照。
- 边界与异常：执行中的任务不可编辑。

**TSK-05 删除任务**（Must）
- 验收标准：
  - AC-TSK-05-1：二次确认后物理删除（含脚本/资源/执行历史）。
- 边界与异常：运行中任务拦截删除。

**TSK-06 执行任务**（Must）
- 用户故事：作为测试工程师，我希望手动触发任务执行并看到队列位置，以便按需运行测试。
- 验收标准：
  - AC-TSK-06-1：任务加入全局串行队列；队列空闲立即执行，忙碌返回排队位置。
  - AC-TSK-06-2：点击「执行」跳转执行监控页（实时状态）。
  - AC-TSK-06-3：执行中任务禁止重复触发（错误码 20003）。
- 边界与异常：同一时间仅执行一个任务，其余排队；返回 `queuePosition` 供前端展示。

**TSK-07 任务重试**（Must）
- 验收标准：
  - AC-TSK-07-1：失败后按 `maxRetries`（默认 3）自动重试，完全重新执行并清理上次临时文件。
  - AC-TSK-07-2：重试等待时间指数退避（`1000 * 2^n` ms）。
  - AC-TSK-07-3：重试过程状态为 `retrying`，耗尽后判定 `failed` 并生成失败报告。
- 边界与异常：重试次数上限可配置；每次重试独立生成执行上下文。

**TSK-08 执行调度（按时间 / 按次数）**（Must）
- 用户故事：作为测试工程师，我希望任务按时间或次数循环执行，以便回归/压测场景下自动连续运行。
- 验收标准：
  - AC-TSK-08-1：手动执行：点一次跑一次（快速验证）。
  - AC-TSK-08-2：按时间循环：配置持续时长，单位支持天/时/分/秒，到时长自动停止。
  - AC-TSK-08-3：按次数循环：配置迭代次数 N，跑满 N 次自动结束。
  - AC-TSK-08-4：循环中单次迭代失败不中断，继续下一次（容错模式）；可随时手动停止。
- 边界与异常：每次迭代独立生成执行上下文与历史记录；迭代间可配置间隔（默认不等待）。

**TSK-09 执行监控**（Should）
- 验收标准：
  - AC-TSK-09-1：实时日志流自动滚动到底部，进度条更新，展示当前迭代 x/N 与调度类型。
  - AC-TSK-09-2：截图缩略图展示，点击放大。
  - AC-TSK-09-3：支持停止执行，停止后已产生的迭代历史保留。
- 边界与异常：监控页轮询（约 2s）拉取状态与日志。

**TSK-10 执行历史与回放**（Should）
- 用户故事：作为测试工程师，我希望每个任务都有完整执行历史，并能回看某次执行的监控全过程。
- 验收标准：
  - AC-TSK-10-1：任务级历史列表，每次迭代独立一条记录（迭代序号/开始时间/结果/耗时/报告）。
  - AC-TSK-10-2：点击历史可打开回放视图，布局与执行监控页一致（日志流 + 截图 + 进度 + 状态）。
  - AC-TSK-10-3：回放视图附「查看完整报告」入口。
- 边界与异常：历史记录随任务保留，删除任务时一并清理。

## 4. 用户流程与交互体验

### 4.1 核心用户流程

**流程 1：AI 录制创建项目（生成脚本）** —— 界面入口 `frontend/index.html`

```
① 打开 AI 录制观测台（index.html）→ 左侧「会话」面板 → 「＋ 新建」会话
② 中部对话区输入起始地址 URL（如 http://localhost:8000/#/login）+ 自然语言任务描述（如“在登录页输入 admin/admin123 登录”）

④ 执行中可切到「代码」面板（CodeMirror，JS/Python/JSON 切换、刷新/复制/保存/运行/导出）；或点「调试器」进入 F12 式页面调试（Elements / Locator / Snapshot / Actions / Console + 实时视图）
⑤ 完成 / 停止后「保存为录制项目」；或「继续追加任务」（复用会话，保留登录态）

```

⑤ 右侧「时间线」Tab 自动记录每一步（可导出 JSON / JS / PY）；「代码」Tab 与 AI 页同构
⑥ 顶栏「⏹ 结束并保存」→ 生成录制项目
```

**流程 3：从项目创建任务并执行**

```
① 项目列表 → 选择 ready 项目 → 「创建任务」

**流程 5：查看与导出测试报告**

① 「测试报告」→ 筛选（任务/计划/状态/时间）→ 打开详情

### 4.2 异常流程

| 编号 | 异常场景 | 处理流程 |
|------|---------|---------|
| E1 | 浏览器启动失败 / 页面崩溃 | 录制回调 `status: failed` + 错误原因 → 界面提示常见原因（路径错误/无头环境缺依赖）→ 可重试 |
| E2 | LLM 未配置 | AI 录制入口置灰 → 引导配置弹窗 → 跳转 LLM 配置页 → 配置完成后恢复 |
| E3 | Runner 不可达 | 启动录制报「执行器未就绪」→ 提供重试与端口检查指引（:9377） |
| E4 | SSE 断连 | 自动重连（指数退避）→ 重连后通过 `/events` 回放环形缓冲补齐缺失事件 |
| E5 | 录制会话失联 | 心跳连续超时 → 状态转「失联」（错误色）→ 提供「强制结束」→ 已收动作仍可保存 |
| E6 | 任务执行失败且重试耗尽 | 完全重试 N 次失败 → 生成失败报告（原因 + 截图）→ 状态 `failed` |
| E7 | 计划部分任务失败 | 单任务失败 → 继续执行后续 → 汇总报告标注失败任务 → 计划状态 `failed` |
| E8 | 定时触发冲突 | 计划执行中再次到点触发 → 拦截并提示「计划执行中」，避免叠加 |

### 4.4 全链路状态流转

```
录制项目：  draft → ready → archived
浏览器录制： pending → recording → (paused) → completed | failed | stopped
AI 会话：   pending → running → completed | failed | stopped | expired(GC 回收)
测试任务：  pending → running → success | failed
                     └→ retrying → running（重试循环，耗尽后 failed）
测试计划：  idle → running → completed | failed
测试报告：  success | failed | skipped（每次执行独立生成，不覆盖）
```

### 4.5 全链路体验要点

- **过程透明**：录制/AI 执行的每一步实时可见，杜绝黑盒等待。
- **可中断可恢复**：任何长耗时操作（录制、AI 探索、任务执行）均可随时停止，且不丢失已产生数据。
- **失败可解释**：每条失败步骤必须给出原因 + 截图，而非笼统报错。
- **产物贯通**：AI 与浏览器录制的产物统一落库，任务/计划/报告链路无差别消费，保证「一次录制，处处复用」。

## 6. 业务规则

1. **任务快照**：任务创建时复制项目脚本，编辑项目不影响已有任务；执行时锁定项目快照。
2. **重试机制**：任务失败后完全重新执行，清理上次临时文件，等待时间指数退避（`1000 * 2^n` ms）。
3. **计划执行**：串行执行，单任务失败后续任务继续执行，最终报告汇总所有结果。
4. **参数传递**：任务模板（paramsSchema）定义参数结构，执行时用户传入实际数据。
5. **并发控制**：单机串行，同一时间仅执行一个任务，不支持并发与分布式（本期范围）。
6. **产物统一**：AI 录制与浏览器录制的产物统一落入项目模型，任务/计划/报告链路无差别消费。
7. **删除语义**：录制项目、任务、计划、报告均为物理删除；删除项目时关联任务同时删除。
8. **执行保护**：运行中的项目/任务/计划禁止删除与重复触发，保证数据一致性。
